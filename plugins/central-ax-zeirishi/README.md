# central-ax-zeirishi（Central AX 税理士事務所パック）

税理士事務所の税理士・職員が、Claude Codeを「安全に」「業務で」使うためのプラグイン。顧問先の情報を守るための安全管理と、日々の業務（顧問先への回答・仕訳・面談記録）を手伝うskillをまとめて入れている。

## インストール

Claude Code内で以下を実行:

```
/plugin marketplace add Central-AX/claude-plugins
/plugin install central-ax-zeirishi@central-ax
```

## 同梱内容

### 安全管理

| 種類 | 名前 | 役割 |
|------|------|------|
| skill | `input-check` | 顧問先の資料・数字・個人情報をAIに入れる前に、3区分（入力可／条件付き／入力禁止）で判定し、マスキング（伏字化）の手順を示す。顧問先の資料が貼られたら、依頼がなくても起動する |
| skill | `office-ai-policy` | 事務所AI・クラウド利用規程、ツール管理台帳、職員教育・誓約の記録、顧問先への説明文を対話で作る |
| skill | `tax-output-check` | AIが作った税務の成果物を、税理士が最終確認する前に検査する。検査は `tax-reviewer` に任せる |
| agent | `tax-reviewer` | 独立した検査役。条文・通達の実在と内容、計算の検算、適用年度、前提の欠落、断定しすぎを確認し、税理士確認欄を付けて返す |

### 業務

| 種類 | 名前 | 役割 |
|------|------|------|
| skill | `client-reply` | 顧問先からの質問に対する回答文案（結論／理由と根拠／顧問先に確認したい事項／注意点）。送信は人が行う |
| skill | `journal-draft` | 領収書・請求書から仕訳候補のCSVを作る。勘定科目は候補、インボイス登録番号の形式チェックと要確認フラグ付き |
| skill | `meeting-note` | 顧問先との面談メモ・文字起こしから、面談記録・宿題・次回確認事項を作る |

業務skillは、どれも最初に `input-check` の原則（入れてよい情報かの確認とマスキング）を確認してから進む。

## 使い方の例

- 顧問先の資料を貼る・読み込ませる → `input-check` が先に区分を確認する
- 「事務所のAI利用規程を作りたい」「ツール管理台帳を作って」 → `office-ai-policy`
- 「この申告書の下書き、チェックして」「この回答、根拠を確認して」 → `tax-output-check`
- 「顧問先からこう聞かれた。回答案を作って」 → `client-reply`
- 「この領収書から仕訳を起こして」 → `journal-draft`
- 「今日の面談メモを記録にまとめて」 → `meeting-note`

## 大事な前提

- **AIは税理士の判断を代わりに行わない。** 税務の結論・顧問先への助言・申告内容の最終判断と責任は税理士にある。このプラグインの出力はすべて「下書き」「候補」「検査結果」として扱う
- **送信・提出・会計ソフトへの登録は人が行う。** このプラグインはメール送信や申告データの提出をしない
- **何を入れてよいかは事務所が決める。** 「条件付き」区分の情報を入れてよいかは、事務所が承認したツール・プランか、学習利用がオフになっているか等で変わる。事務所のルールを先に決めておく（`office-ai-policy` で作れる）

## 日税連ガイドラインとの関係

日本税理士会連合会「税理士事務所のためのAI・クラウド活用ガイドライン」（2026年9月策定）について、公開されている情報で示されている論点（入力する情報の区分、ツール・プランの選定、DPA（データ処理契約）や学習利用の設定の確認、職員の利用管理、税理士による最終判断）に沿って作った。

ガイドライン本体と規程ひな型は会員専用ページにあり、このプラグインはその本文を参照していない。各事務所で手元のガイドライン本体と照合したうえで使うこと。`office-ai-policy` にガイドライン本体や規程ひな型を渡すと、そちらの構成・文言を優先して作る。
