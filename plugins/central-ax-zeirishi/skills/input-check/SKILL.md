# 入力前チェック（input-check）

顧問先の情報をAIに入れる前に、「入れてよい情報か」「どう伏せれば入れてよいか」を判定する。税理士には守秘義務があり、顧問先の情報は事務所の外に出す前に必ず区分を確認する。

## 原則

- **迷ったら入れない。** 区分の判断に迷うときは入力せず、税理士・事務所の責任者に確認する
- **入力禁止の情報は、どんな条件でも入れない。** マイナンバー（個人番号）、預金口座番号・カード番号、パスワード・認証情報、健康・病歴など要配慮個人情報
- **条件付きの情報は、事務所が承認したツール・プランでのみ扱う。** 学習利用オフ・データ処理契約（DPA）の確認などを事務所が済ませていることが条件。確認できない場合はマスキングしてから入れる
- **必要な分だけ入れる。** 作業に要らない列・ページ・個人情報は最初から外す
- 区分の具体例表・マスキング手順・対応表の作り方は `references/classification.md` を読む

## 手順

1. 何を入れようとしているかを確認する
   - 会話に貼られた文章・数字、読み込もうとしているファイル（ファイル名・フォルダ名からも推測する）
   - 源泉徴収票・扶養控除等申告書・給与支払報告書・マイナンバーのコピー・通帳のコピーなど、入力禁止の情報が含まれやすい書類は、読み込む前にユーザーに確認する
2. 3区分で判定する（`references/classification.md` の具体例表を使う）
   - 入力可 / 条件付き / 入力禁止 を、情報の項目ごとに示す
3. 条件付きの情報がある場合、事務所の承認状況を確認する
   - 事務所のAI利用規程・ツール管理台帳があればそれに従う。無ければ `office-ai-policy` で作ることを提案する
   - 承認状況が分からない場合は、マスキングしてから進める
4. 入力禁止の情報・マスキングが必要な情報があれば、伏せ方を示す
   - ユーザーが自分で伏せる手順を案内する（伏せる前の原本をAIに渡さない）
   - 氏名と仮名の対応表は事務所内（AIに渡さない場所）で管理する
5. 判定結果を短く報告してから、本来の作業に戻る
   - 例:「区分を確認しました。口座番号が含まれているので伏字にしてください。それ以外は条件付き区分で、事務所の承認済みツールであれば進められます」

## すでに入力禁止の情報が入ってしまったとき

- 以降の出力（回答文・CSV・記録）にその情報を書き写さない。引用が必要なら伏字にする
- ファイルの場合は、伏字にした版を作ってもらい、以降はそちらを使う
- 何が入ったか（項目の種類だけ。値は書かない）を伝え、事務所のルールに従って責任者に報告するよう案内する。報告が必要かどうかの判断は事務所が行う
