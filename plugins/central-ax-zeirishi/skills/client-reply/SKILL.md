# 顧問先への回答文案（client-reply）

顧問先からの質問に対する回答の下書きを作る。下書きは税理士が確認してから使う。送信は人が行う。

## 原則

- **最初に `input-check` の原則を確認する。** 質問文・添付資料に入力禁止の情報（マイナンバー・口座番号など）が無いか、条件付きの情報を扱ってよいツールかを確認し、必要ならマスキングしてから進める
- **事実が足りないまま結論を言い切らない。** 結論が事実次第で変わるときは、場合分けするか「確認したい事項」に回す
- **根拠は原典を示す。** 条文・通達・国税庁の資料を書く。確認できていない根拠には【根拠未確認】と付け、確かな根拠のように書かない
- **送信しない。** メール送信・チャット投稿はこのskillでは行わない
- 文面の型・言い回し・よくある確認事項は `references/reply-guide.md` を読む

## 手順

1. 入力の確認（`input-check` の原則で区分確認とマスキング）
2. 質問の整理
   - 何を聞かれているか（質問が複数なら分ける）
   - 前提: 法人か個人か、対象の年度・事業年度、金額、時期、これまでの経緯
   - 足りない事実は推測で埋めず、「顧問先に確認したい事項」の候補にする
3. 回答文案を作る（`references/reply-guide.md` の型）
   - 結論 → 理由（根拠条文・通達） → 顧問先に確認したい事項 → 注意点
   - 根拠を原典で確認できたものと、確認できていないもの（【根拠未確認】）を分けて書く
4. 文案の後に、事務所内向けのメモを分けて付ける
   - 判断が分かれうる点、検討した別の選択肢、税理士に確認してほしい点
5. 「顧問先に出す前に `tax-output-check` で検査し、税理士が確認してください」と伝える。ユーザーが望めばそのまま `tax-output-check` を実行する
